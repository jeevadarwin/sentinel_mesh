1. PROJECT OVERVIEW & PURPOSE
--------------------------------------------------------------------------------
Sentinel Mesh is an Autonomous 8-Agent Security Operations Centre (SOC) Intelligence 
Platform designed to automate real-time alert triage, threat enrichment, 
multi-agent adversarial debate, human-in-the-loop (HITL) decision-making, and 
sandboxed firewall containment.

The platform ingests real Suricata IDS/IPS network security alerts (e.g. from 
the WRCCDC 2018 dataset) and orchestrates an autonomous mesh of 8 specialized AI 
agents that analyze, debate, quantify risk, and recommend response actions.

Key Value Proposition:
- Eliminates SOC alert fatigue through multi-perspective LLM debate.
- Standardizes threat analysis using schema-validated Pydantic outputs.
- Ensures fault tolerance via a multi-provider LLM fallback chain.
- Provides real threat enrichment (AbuseIPDB with TTL caching & static MITRE fallback).
- Implements active network containment via a standalone Sandbox Firewall.
- Features a real-time Cyberpunk-themed telemetry dashboard powered by SSE (Server-Sent Events).


2. ARCHITECTURE & TECHNOLOGY STACK
--------------------------------------------------------------------------------
Backend:
- Language: Python 3.10+
- Web Framework: FastAPI / Uvicorn (Asynchronous REST API + SSE)
- Data Validation: Pydantic v2 (Strict schema enforcement)
- HTTP Client: HTTPX (Async HTTP requests for LLM calls and enrichment)
- Testing Framework: Pytest / Pytest-Asyncio

Frontend:
- Core Technologies: Vanilla HTML5, Vanilla JavaScript (ES6+), Vanilla CSS3
- Design System: Custom Cyberpunk / Dark Mode aesthetic (CSS Variables, glassmorphism, micro-animations)
- Typography: Google Fonts (Inter for UI, JetBrains Mono for telemetry/logs)
- Data Transfer: EventSource SSE (Server-Sent Events) for real-time token telemetry & agent debate streaming
- Dependencies: Zero external npm packages / zero build steps required

Sandbox Firewall Service:
- Standalone FastAPI application running on port 8002
- In-memory active blocklist simulation (IP address containment API)


3. THE 8-AGENT MESH TOPOLOGY BREAKDOWN
--------------------------------------------------------------------------------
The platform utilizes an 8-agent multi-perspective debate and resolution topology:

1. Triage Agent (🔍):
   - Primary Role: Initial alert parsing & urgency classification.
   - Task: Extracts key indicators (Source IP, Destination IP, Alert Signature, Category) and assigns an Urgency Rating (LOW, MEDIUM, HIGH, CRITICAL).

2. Threat Intel Agent (🌐):
   - Primary Role: IOC Extraction & Threat Enrichment Analysis.
   - Task: Extracts IOCs from Suricata alerts, queries AbuseIPDB (or static MITRE ATT&CK fallback table), evaluates IP confidence score, domain reputation, and associated MITRE TTPs.

3. Correlation Agent (📊):
   - Primary Role: Historical & Multi-Alert Contextual Analysis.
   - Task: Correlates incoming alerts against past telemetry, detecting recurring attack patterns, lateral movement, or brute-force clusters.

4. Threat Defense Advocate / Prosecutor (⚡):
   - Primary Role: Malicious Prosecutor.
   - Task: Builds the strongest possible argument that the alert represents an active, high-severity threat requiring urgent intervention.

5. Benign Defense Advocate / Defense Attorney (🛡️):
   - Primary Role: False-Positive Advocate.
   - Task: Identifies potential benign explanations (misconfigurations, authorized security scans, benign admin activity) to prevent false positives.

6. Business Impact Agent (💼):
   - Primary Role: Asset & Operational Risk Assessor.
   - Task: Evaluates the potential business blast radius, target asset criticality, data loss risk, and operational downtime impact.

7. Containment / Response Agent (🚨):
   - Primary Role: Remediation & Mitigation Specialist.
   - Task: Generates actionable containment playbooks (e.g. Isolation, IP Block, Host Quarantine, Firewall Rule Addition) and assigns a Risk Level to response options.

8. Commander / Coordinator Agent (⚖️):
   - Primary Role: Debate Moderator & Final Decision Engine.
   - Task: Reviews arguments from all agents, evaluates the deterministic confidence gap (|Threat_Conf - Benign_Conf| > 0.25), issues the final verdict (TRUE_POSITIVE, FALSE_POSITIVE, SUSPICIOUS), and routes high-risk cases to the Human-in-the-Loop Approval Gate.


4. MULTI-LLM ORCHESTRATION & FALLBACK CHAIN
--------------------------------------------------------------------------------
Sentinel Mesh utilizes a fault-tolerant multi-provider LLM fallback orchestrator (`app/llm/provider.py`) to prevent service disruptions:

Provider Priority Order:
1. NVIDIA NIM (Primary — High performance / Low latency): `meta/llama-3.1-70b-instruct`
2. Groq Cloud (Secondary — Fast free-tier cloud fallback): `llama-3.3-70b-versatile`
3. Google Gemini (Tertiary — Free cloud provider): `gemini-1.5-flash`
4. Ollama / LM Studio (Local Fallback — Fully offline capability): `gemma4:latest` / `local-model`

Fault-Tolerance Mechanism:
- If a provider is unconfigured (empty API key), rate-limited (HTTP 429), or times out, the orchestrator instantly logs a warning and advances to the next provider in the chain.


5. THREAT INTELLIGENCE & ENRICHMENT ENGINE
--------------------------------------------------------------------------------
Module: `app/enrichment/`
- `abuseipdb_client.py`: Queries AbuseIPDB v2 API (`GET /api/v2/check`).
- In-Memory TTL Cache: Stores query results for 3600 seconds (1 hour) per IP address to conserve API quota.
- Fallback System: If `ENRICHMENT_API_KEY` is missing or API call fails, gracefully falls back to a curated static MITRE ATT&CK lookup table, flagging `fallback_used = True`.
- Extracted Fields: `abuse_score`, `reports_count`, `country_code`, `asn`, `mitre_tactics`, `mitre_techniques`, `limitations`.


6. SANDBOXED CONTAINMENT & HITL APPROVAL GATE
--------------------------------------------------------------------------------
Standalone Firewall Service: `sandbox_firewall/main.py` (Port 8002)
- Endpoints:
  - `POST /block` : Adds an IP address to active firewall blocklist.
  - `GET /blocked/{ip}` : Verifies if an IP is currently blocked.
  - `GET /status` : Returns full firewall state & count of active blocks.

Approval Gate Flow (`app/routers/decisions.py`):
1. When the Commander recommends containment (e.g., Block IP), the case is assigned status `PENDING_APPROVAL`.
2. A SOC analyst reviews the recommendation in the UI and clicks "Approve".
3. The backend executes `sandbox_client.post_block(ip)` followed by an immediate `sandbox_client.verify_blocked(ip)` verification round-trip.
4. Upon positive verification, the alert status updates to `CONTAINED`.


7. FRONTEND DASHBOARD & TELEMETRY ENGINE
--------------------------------------------------------------------------------
Located in `sentinel_mesh/frontend/`:
- `index.html`: Main SOC Control Center layout.
- `styles.css`: Cyberpunk styling tokens, flexbox/grid layout, dark palette.
- `app.js`: Connects to backend SSE endpoints (`/alerts/stream`), handles real-time token telemetry chart animations, agent node status flashing, alert list updates, and detail panel rendering.
